## 这次回答的核心问题

**能按真实雪道图建模，但不是“自动抓一张官方图”就行。**

推荐做法是 **L2：按官方雪道图重绘矢量图**：

- 以雪场官方雪道图为参考，人工描出每条雪道的中心线、缆车线、山顶/山底/缆车站点。
- 保留真实雪道名称、难度、相对位置和分叉关系。
- 输出 SVG / GeoJSON（本地坐标即可，不需要真实经纬度）。
- 每条雪道绑定稳定 ID，状态变化只改数据，不动图形。
- 视觉上标注“基于官方雪道图重绘”，正式商用/公开分发需要雪场授权。

### 三种精度

| 方案 | 效果 | 交互/动态 | 授权 | 工作量 |
|---|---|---|---|---|
| L1 官方图直接做底图 | 最像官方图 | 弱，只能盖色块/热点 | 必须授权 | 低 |
| **L2 按官方图重绘矢量（推荐）** | 接近官方图，可定制 | 强，可逐条染色/动画 | 重绘也建议授权 | 中，1–2 天/雪场 |
| L3 原创抽象示意 | 不像真实雪道 | 强 | 不涉及 | 低 |

OSM/OpenSkiMap 在崇礼的雪道/缆车覆盖很不完整（万龙只映射到极少数缆车），不能作为主数据源。

## 动态时间轴怎么实现

每条雪道绑定状态事件：

```text
{ trailId, at, status: open | closed | expected, reason, source, official }
```

- 当前时间之前：取最后一条 `open/closed` 事件，显示实线开放/灰色关闭。
- 当前时间之后：只展示官方 `expected`，显示虚线 + 光晕，不能标成“已开放”。
- 拖动/点击时间轴：
  - 地图逐条重新计算颜色、线型、光晕
  - 开放数量、各级别数量同步变化
  - 事件列表高亮当前时间
- 时间轴节点来自官方公众号/公告，不凭空生成。
- 没有历史数据时，时间轴从第一次采集开始，不伪造过去。
